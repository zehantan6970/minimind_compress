Weight-only INT8 Quantization, Explained

A kernel-free approach that runs on Pascal GPUs and CPU. Built for MiniMind-O; benchmark script bench_quant_omni.py.

1. Why quantize?

Neural-network weights are normally stored as FP32 (4 bytes) or FP16/BF16 (2 bytes). Most of those bits are not needed for the model to behave correctly. Quantization maps weights to a low-bit integer type (here INT8, 1 byte), cutting storage and memory bandwidth roughly in half (vs FP16) or to a quarter (vs FP32).

Quantization does not change the parameter count A 113M model stays a 113M model. Only the number of bytes per parameter changes. In this project the model size drops from about 452 MB (FP32) to 207 MB (INT8).

2. Weight-only vs activation quantization

  • Weight-only (what we do): only weights are stored as INT8; activations stay in FP32. At the forward pass weights are de-quantized and a normal FP32 matmul runs. No special kernels, maximum compatibility.
  • Full INT8 (weights + activations): requires INT8 Tensor Cores / kernels (e.g., via bitsandbytes, TensorRT, ONNX QLinearMatMul). Faster on supported hardware, but unavailable on Pascal (GTX1070, sm_61).

3. Per-channel linear quantization (the math)

scale = max(|w|) / 127 # one scale per output channel w_q = clamp( round(w / scale), -127, 127 ) # integer weights actually stored w_hat = w_q * scale # de-quantized at the forward pass err = w_hat - w # round-to-nearest error

This is the simplest PTQ method, often called RTN (round-to-nearest) — no training, no calibration data. Per-channel scales keep large-magnitude channels from dominating the error.

4. W8Linear: code with comments

import torch, torch.nn as nn

class W8Linear(nn.Module):
    # Drop-in replacement for nn.Linear: int8 storage, FP32 compute.
    def __init__(self, linear: nn.Linear):
        super().__init__()
        w = linear.weight.data.float()
        # per-output-channel scale (symmetric, range -127..127)
        scale = w.abs().max(dim=1, keepdim=True).values / 127.0
        wq = torch.clamp(torch.round(w / scale), -127, 127).to(torch.int8)
        self.register_buffer("w_q", wq)          # 1 byte per weight
        self.register_buffer("scale", scale)
        self.bias = None if linear.bias is None \
            else linear.bias.data.clone()

    def forward(self, x):
        w = self.w_q.float() * self.scale          # de-quantize -> FP32
        return torch.nn.functional.linear(x, w, self.bias)

7. PTQ / RTN / QAT, and when to escalate

  • PTQ (post-training): quantize after training. RTN is the simplest PTQ.
  • QAT (quantization-aware training): insert fake-quant nodes during training so the model learns around quantization error. Higher accuracy, but requires retraining.
  • If INT8 degrades on sensitive layers (attention / lm_head), either skip them (ffn), use mixed precision, or fall back to QAT.
Quality gate After quantizing, run the exact same evaluation as the FP model and compare. If accuracy drops beyond your threshold, revert. Do not deploy a quantized model just because it is smaller.
