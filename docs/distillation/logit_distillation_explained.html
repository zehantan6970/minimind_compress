Knowledge Distillation, Explained

MoE teacher 315M → Dense student 113M. Sequence-level and logit-level KD on MiniMind-O, with real data.

1. What is knowledge distillation?

Knowledge distillation (KD) transfers capability from a large teacher to a small student. There are three levels:

LevelTeacher targetWhen
Sequence / responseFinal text (one-hot hard labels)Deterministic tasks with a known answer
LogitPer-position distribution over the whole vocabOpen / style tasks; "dark knowledge"
FeatureIntermediate hidden statesSame-shaped models (or a projection)
KD does not change model size The 315M → 113M reduction comes from architecture choice (MoE 4 experts → Dense 1 FFN). KD only moves the capability; it does not shrink parameters.

2. Hard vs soft labels, temperature, dark knowledge

  • Hard label: one-hot — correct token = 1, all others = 0. Trained with cross-entropy.
  • Soft label: the teacher's full probability distribution, including non-zero mass on plausible alternatives.
  • Temperature T: softmax(z/T). Higher T flattens the distribution and reveals the relative mass of near-misses (T = 2..4).
  • Dark knowledge: the information carried by the probabilities of wrong answers — e.g., after "Why", the next word should be a question auxiliary, not any random token.
Real example — "Tell me a joke" → "Why" → next token At T=4 the teacher gives a cluster: don 0.0178, did 0.0152, do 0.0077, was 0.0069, have/does/can/is/are/could 0.003..0.005. A hard label only says "did". The soft label teaches the whole auxiliary-verb cluster and its ranking.

3. The loss (and why T²)

p_t = softmax(z_t / T) # teacher soft target p_s = softmax(z_s / T) # student soft distribution L = α · T² · KL(p_t ‖ p_s) + (1 − α) · CE(y, softmax(z_s))

Dividing by T shrinks the softmax gradient by about 1/T². Multiplying the KL term by T² restores the scale so the soft and hard terms are comparable (Hinton).

4. Why MoE and Dense can distill together

Logit KD does not require matching internals — only matching outputs. Both lm_head layers are 768 → 6400 over the same tokenizer, so column j is the same word in both. The internal 4-expert MoE vs 1-FFN Dense is irrelevant to the alignment.

h_t, _, _ = teacher.thinker(x) # teacher internals z_t = teacher.lm_head(h_t) # [B, T, 6400] h_s, _, _ = student.thinker(x) # student internals z_s = student.lm_head(h_s) # [B, T, 6400] -> same shape

5. Online teacher + training loop (comments)

import torch, torch.nn.functional as F

def kd_step(batch, teacher, student, T=4.0, alpha=0.3):
    teacher.eval()
    with torch.no_grad():
        zt = teacher.lm_head(teacher.thinker(batch.x)[0]).detach().float()
        pt = torch.softmax(zt / T, dim=-1)          # soft target
    zs = student.lm_head(student.thinker(batch.x)[0]).float()
    # soft KL, teacher as target (answer positions only; mask uses y != -100)
    log_ps = F.log_softmax(zs / T, dim=-1)
    kl = F.kl_div(log_ps, pt, reduction="none").sum(-1)
    kl = (kl * batch.mask).sum() / batch.mask.sum()
    ce = F.cross_entropy(zs.transpose(1, 2), batch.y, ignore_index=-100)
    loss = alpha * (T * T) * kl + (1 - alpha) * ce   # T² compensation
    loss.backward()
    return loss, kl, ce
# Only student.thinker is in the optimizer; teacher is frozen.

7. The key lesson: hard for commands, soft for chat

Teacher ceiling The MoE teacher hedges on commands during free generation, so soft labels conflict with hard templates there (soft KL stalls around 1.7; command accuracy drops to 64.2%). Under teacher forcing it is correct at mid-span positions — the evasion happens only at the free-generation opening.
Per-domain strategy Deterministic commands: hard labels, α ≈ 0 (75.5%). Open chat / jokes: soft labels, α ≈ 0.7. Always evaluate the teacher on your task before trusting its soft targets.

8. Inference: autoregressive with KV cache

prompt → apply_chat_template → model.generate loop: argmax next token → append it (KV cache) → until EOS decode → answer

Training is teacher-forced (whole answer in, one parallel pass). Inference is autoregressive (one token at a time, no loss, no backward). Greedy (temperature=0) is deterministic and fits command control.
